# ASME Social Hub audit — November 1, 2026

The changes identified below have been implemented locally. See [implementation and verification notes](HUB_IMPLEMENTATION_2026-11-01.md). This audit preserves the findings from before implementation.

## Assessment

The hub has a coherent visual identity and substantial working functionality. The remaining work is concentrated in preventing avoidable publishing failures and lost edits, keeping officers informed, and making mobile information easier to scan. Resolve the P1 issue and the officer workflow P2 issues before a wider launch.

This audit combines separate design, usability, and launch/member-experience reviews. Design and usability agents were relaunched after the initial agents stopped before delivering final reports; their completed reviews validate the findings below. Browser observations concern the local repository version, not an independently verified live deployment.

## Fix first

| Priority | Finding and impact | Recommended change | Evidence |
| --- | --- | --- | --- |
| P1 | **An unpublishable Instagram caption can still be saved.** A browser check successfully exported a campaign with a 2,300-character description while its preview reported the 2,200-character caption limit. The dispatcher later generates that caption and marks the channel failed. | Validate the final generated caption before uploading or saving whenever an Instagram channel is enabled. Show a focused error and the remaining character budget. | `docs/app.js:206–209`; `docs/flyer-preview.mjs:97`; `docs/caption.mjs:35`; `scripts/dispatch.mjs:70–77` |
| P2 | **Closing the editor silently loses changes.** Escape and Close dismiss a dirty editor; reopening resets the form. A typed title disappeared in the browser check. | Track dirty state and offer Keep editing / Discard. Add reload protection and, if appropriate, recoverable local drafts. | `docs/app.js:140`, `:183`, `:269` |
| P2 | **Changing event type overwrites officer choices.** Defaults replace the location, food choice, and Instagram scheduling fields. A custom location was erased and a 14:15 feed time reset to 12:00. | Apply defaults only to untouched fields, or offer an explicit Apply type defaults action. | `docs/app.js:139`, `:272` |
| P2 | **Campaign status becomes stale while the hub stays open.** Campaigns load once; the periodic campaign render reuses memory while dispatcher health refreshes independently. A recent successful check can sit beside obsolete Pending badges and receipts. | Add Refresh and a campaign sync timestamp. Refresh on tab focus and after dispatcher completion without replacing dirty editor state. | `docs/app.js:108`, `:132–136`, `:278` |
| P2 | **The review count does not lead to the affected campaigns.** It is a plain statistic, and its count can include old failed or missed campaigns already removed from the home list. | Open an attention queue from the count, including failed and missed steps, explanations, and next actions. | `docs/app.js:109`; `docs/home-campaigns.mjs:4` |

## Design and mobile usability

These are observed design issues and recommendations, not claims of formal accessibility noncompliance.

| Priority | Finding | Recommended change | Evidence |
| --- | --- | --- | --- |
| P2 | **The phone overview comes too late.** At 390px, routine posting health and the review count sit roughly 2,800px down the captured page, below five large campaign cards. Failed/stale dispatcher health is promoted, but campaign attention is not. | Put a compact, actionable attention summary above campaigns. Keep detailed receipts in campaign details or expandable sections. | `docs/app.js:109`, `:127`; `docs/hub-design.css:153` |
| P2 | **Posting information is too small and fragmented.** Channel status uses 9px uppercase and dates use 10px; GroupMe follow-up text wraps into several short lines. | Use readable sentence-case labels and stacked channel rows on narrow cards, or emphasize one clear next action. | `docs/hub-design.css:153–163` |
| P2 | **Phone onboarding hides the explanation.** Mobile removes the preview-mode explanatory copy, leaving Connect repository without nearby context about the GitHub token or what access enables. | Retain a one-sentence explanation and a clear Set up access action. | `docs/styles.css:455`; mobile dashboard capture |
| P3 | **Flyer headers look washed out.** Cropped 100px artwork strips at 24% opacity plus a pale gradient turn embedded flyer text into visual noise. | Choose a clean decorative header or a recognizable thumbnail with a deliberate preview action. | `docs/hub-design.css:125–128` |

Keep the warm palette, display typography, sidebar branding, and clear primary campaign action. The strongest design improvement is clearer information priority and readable operational details.

## Validation and limits

- `npm test`: **252 passed, 0 failed**.
- `npm run check`: configuration, campaign data, and JavaScript syntax passed.
- The readiness reviewer also ran 13 focused member-event/calendar/PWA tests successfully.
- The completed readiness second pass confirmed all 8 real public campaigns have both calendar `.ics` files and generated static event pages present.
- Browser checks covered desktop and phone rendering, editor loss/default-reset/caption-export behavior, and the actual MATLAB member event at 390px. Its flyer and calendar actions loaded without horizontal overflow.
- No source fixes, live posts, announcements, or production repository writes were performed as part of this audit. This report is the audit artifact.
- Missing credentials in the local environment do not establish whether GitHub Actions secrets are configured. Production integration readiness was not independently certified.
- LinkedIn is intentionally paused. Offline member pages and flyers are a documented limitation, not a newly discovered regression.
- An oversized sidebar in a full-page browser capture was a screenshot artifact. The measured live desktop sidebar was 240px wide; it is excluded from the findings.

## Suggested implementation sequence

1. Block invalid Instagram captions before save and preserve officer edits when event types change.
2. Protect dirty editors from accidental dismissal and reload.
3. Add campaign refresh, last-synced feedback, and an actionable attention queue.
4. Move attention above mobile cards and improve channel-status readability and onboarding copy.
5. Unify member previews and shared pages, add social metadata, and improve error recovery.
6. Refine decorative artwork headers after the workflow changes.
